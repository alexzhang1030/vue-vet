# Vue Vet context map

Open the record routed for the code or decision you are about to change. These records hold durable project judgment; temporary execution state belongs in GitHub issues and the root roadmap.

| When changing | Read | Why |
| --- | --- | --- |
| Product scope, target users, scoring intent, or release promises | [goal](./goal.md) and [root roadmap](../../ROADMAP.md) | Defines what Vue Vet is trying to become and what it deliberately refuses before Beta. |
| Dependencies, tool ownership, Rust-only constraints, or version pins | [technology stack](./technology-stack.md) and [Vize compatibility baseline](../../docs/vize-compatibility.md) | Explains why Vize and Oxc own the semantic stack, why analysis dependencies are pinned, and how Vize upgrades are validated. |
| Crate boundaries, data flow, diagnostics, project graph, reporters, or public APIs | [architecture](./architecture.md) and [analysis-stack ADR](../../docs/adr/0001-analysis-stack.md) | Defines the stable Vue Vet-owned boundaries around third-party parsers and semantic engines. |
| Reactivity graph facts, tracking scopes, module summaries, tracer completeness, or CLI reactivity digest | [reactivity tracer](./reactivity-tracer.md), [gotchas](./gotchas.md), [literature matrix](./research/reactivity-tracer-literature.md), [oracle](../../crates/vue_vet_reactivity/oracle/README.md), [JSON output](../../docs/json-output.md) | Static tracer goals; CLI/JSON digest proves tracer ran even when score is clean. |
| Rule IDs, fixtures, source spans, deterministic output, configuration, or completion checks | [conventions](./conventions.md) | Records deliberate engineering rules that contributors and agents must preserve. |
| Ecosystem practice suggestions (`recommendation`, VueUse recipes, score exclusion) | [architecture](./architecture.md) (`vue_vet_practice`), [goal](./goal.md), [JSON output](../../docs/json-output.md) | Practice channel is fact-driven recipes in a dedicated crate; not a parallel pattern engine. |
| Safe edit producers, fix preview/application, atomic writes, or rollback | [architecture](./architecture.md), [conventions](./conventions.md), [edit model](../../docs/edit-model.md), and [gotchas](./gotchas.md) | Defines how edits stay attached to active findings, validate before mutation, and fail closed at the current single-file limit. |
| Vize upgrades, offsets, SFC surface extraction, parallel pattern engines, or score stability | [gotchas](./gotchas.md) | Lists traps already identified and the evidence required before changing the current approach. |
| npm launcher, native binaries, release tags, or install matrix | [technology stack](./technology-stack.md), [architecture](./architecture.md), and [install docs](../../docs/install.md) | Thin JS launcher only; platform packages and release/rollback rules. |
| Thin VS Code reactivity visualization (decorations / TreeView) | [reactivity tracer](./reactivity-tracer.md), [JSON output](../../docs/json-output.md), and [`editors/vscode/README.md`](../../editors/vscode/README.md) | Editor host shells out to CLI JSON; no analysis logic in TypeScript. Full LSP remains issue #12. |
| CLI `--explain` / rule or finding documentation | [JSON output](../../docs/json-output.md) (`--explain`), [architecture](./architecture.md) (stable docs path), issue [#12](https://github.com/alexzhang1030/vue-vet/issues/12) | Rule id early-exit; finding id scans then matches opaque `diagnostics[].id` and nests rule docs. Not the LSP yet. |
| Project session / shared scan+explain for CLI·LSP·MCP | [architecture](./architecture.md) (`vue_vet_session`), [JSON output](../../docs/json-output.md), issue [#12](https://github.com/alexzhang1030/vue-vet/issues/12) | Long-lived session owns config, cache, analyze, explain, workspace path bounds; adapters stay thin. |
| Thin diagnostics LSP (`vue-vet --lsp`) | [architecture](./architecture.md) (`vue_vet_lsp`), issue [#12](https://github.com/alexzhang1030/vue-vet/issues/12) | Stdio LSP over session; overlays + versioned publish; safe quick-fix code actions; finding id in `data`. |
| Thin MCP agent tools (`vue-vet --mcp`) | [architecture](./architecture.md) (`vue_vet_mcp`), issue [#12](https://github.com/alexzhang1030/vue-vet/issues/12) | Stdio JSON-RPC tools: scan, explain, safe-fix preview; workspace path bounds; never applies edits. |
| Props member inspect (`props.count`) or binding picker UX | [reactivity tracer](./reactivity-tracer.md) (graph v7+ `property` / `to_path`; v8 module-qualified `to_id`) and [JSON output](../../docs/json-output.md) | Digest carries member path; TUI/VS Code filter inbound by property. |
| Cross-file `:foo` → child `props.foo` | [reactivity tracer](./reactivity-tracer.md) (A6 Prop edges) | Static bare-identifier binds only; structural `component_nav` is not prop dataflow. |
| Component uses / used_by navigation | [project graph](../../docs/project-graph.md) (`Component navigation`) and [JSON output](../../docs/json-output.md) (`component_nav`) | Structural `ComponentUsage`/`AutoComponent` only — not prop dataflow. |
| CLI project walks, cache keys, or `node_modules` / symlink installs | [gotchas](./gotchas.md) (`Package directories can look like source files`) | Skip `node_modules`; only read paths that are files after symlink resolution. |
| Project import resolution, scoped packages, tsconfig / `.nuxt` paths, Nuxt component auto-import names | [project graph](../../docs/project-graph.md), [gotchas](./gotchas.md), [technology stack](./technology-stack.md) | `oxc_resolver` bundler resolution; Nuxt component naming (`.client`, path prefix, `.nuxt` dts); no Vite/Nuxt config execution. |
| Current implementation order or delivery status | [GitHub tracker](https://github.com/alexzhang1030/vue-vet/issues/14) and [root roadmap](../../ROADMAP.md) | Issues are the live execution plan; the roadmap records milestone intent and release gates. |
| Precision corpus, performance scan modes, or release quality gates | [quality gates](../../docs/quality-gates.md), [quality baselines](../../docs/quality-baselines.md), [conventions](./conventions.md) (CodSpeed/Codecov), issue [#13](https://github.com/alexzhang1030/vue-vet/issues/13) | Checksummed corpus, precision labels, scan-mode benches, `compat-matrix`; release blocks on quality gates. |

Related records should be cross-linked. When a new record or important heading is added, update this map in the same change.
